# 企业资产 · 影子端点专项扫描 运行指引

> 适用：对**已获授权的**组织内部 Java/Web 资产开展影子端点（Druid/Swagger/Actuator/.git/中间件等）自查。
> 工具：ShadowScan（`shadowscan.py` 源码；也可用 `zipapp` 自行打包为单文件。零第三方依赖，需 Python 3.8+）。

## 0. 执行前提（必须满足，否则结果不可信或不合规）

1. **授权**：本次为组织授权的内部安全自查/授权测试范围；命令中必须带 `--authorized`，并保留审计日志。
2. **网络可达**：必须在**能直连目标内网**的位置运行（办公网内 / VPN 直连且 DNS 返回真实内网 IP / 指定的扫描机）。
   - 自检：`curl -s -o /dev/null -w "%{http_code}" --max-time 3 http://<某域名>`，能返回 2xx/3xx/4xx 即为可达。
   - 若域名解析出 `198.18.0.x` / `100.64.x.x` 等保留段或全部超时 → 环境不对，**不要采信 0 命中结果**（假阴性）。
3. **错峰低并发**：内网生产系统建议 `--max-workers 8~12`、`--timeout 4`；避开业务高峰。

## 1. 资产清单准备

`assets.txt` 每行一个目标，支持：URL / 域名 / IP / IP:端口，# 注释：

```
# 生产
http://app.example.cn
http://app.example.cn/portal        # 带上下文的应用写入口 URL
app2.example.cn                     # 域名：自动探测常见 Web 端口
10.0.0.10:8080                       # 显式端口
# 测试/预发
http://test.example.cn
```

建议：生产与测试分开文件、分开扫描；首次先放 **5~10 个已知可达**的小批量验证，再扩全量。

## 2. 推荐命令

**生产模式（推荐）**：AI 研判 + 自适应扩探一键开启。本工具定位是「找得到 + 看得准」——
规则库保证覆盖，AI 保证精准（误报裁决 / 证据验证 / 发现规则库外的端点）：

```bash
source env.sh
python3 shadowscan.py --targets assets.txt --production --authorized \
    --rate-limit 5 --jitter 0.3 -o scan_result_$(date +%m%d)
```

> `--production` ≡ `--ai --adaptive`；AI 不可用时自动降级为纯规则扫描，不阻塞流程。
> 若确实只要纯规则结果（如网络受限、不允许外发数据），去掉 `--production` 即可。

### 其它常用组合

```bash
# 方式A：源码运行
python3 shadowscan.py --targets assets.txt \
    --weak-check --key-check --max-workers 8 --timeout 4 \
    --authorized -o scan_result_$(date +%Y%m%d_%H%M)

# 方式B：单文件运行（可选，需自行打包）
python3 shadowscan.pyz --targets assets.txt \
    --weak-check --key-check --max-workers 8 --timeout 4 \
    --authorized -o scan_result_$(date +%Y%m%d_%H%M)

# 大批量（多批 / 多机 / 断点续跑）用编排脚本
bash tools/batch_scan.sh --targets assets.txt --batch 150 --two-stage
```

参数要点：
- `--authorized`：必填（合规声明），不加直接拒绝；
- `--weak-check`：仅内置默认口令表（Druid ≤3 组合），不爆破、不发大量登录；
- `--key-check`：Shiro 默认 Key 确定性验证，需系统有 `openssl`；
- `--resume` / `--shard i/n` / `--ai-only`：断点续跑 / 分片 / 两阶段 AI（详见 README「大规模扫描」）；
- `--rate-limit`：仅约束 HTTP 请求（端口探测不受限），内网可不用。

## 3. 结果解读与复核

输出目录包含：
| 文件 | 内容 |
|---|---|
| `report.md` | 汇总报告（风险摘要/严重项/按站点/命中清单/整改建议）→ 可直接阅读 |
| `findings.csv` | Excel 明细 |
| `findings.jsonl` | 机器可读 |
| `scan.log` | 审计日志（操作者/资产/过程） |

**必须复核命中项**（防止误报）。两个层次，建议先用 ★：

**① ★ 验证层（推荐，自动出结论）** —— 证据驱动研判：回抓真实响应构建证据包，连同证据交 AI 判断，输出「确认危害 / 疑似 / 已排除」三档：
```bash
python3 tools/verify_layer.py --findings scan_result_xxx/findings.jsonl --out verify_out
# 可选：允许 AI 提议额外端点做多轮追问（受白名单约束、全程审计留痕）
python3 tools/verify_layer.py --findings scan_result_xxx/findings.jsonl --out verify_out --ai-probe-rounds 2
```
证据包含：状态码 / Content-Type / 长度 / 正文片段(脱敏) / **重定向链** / **认证失败特征** / catch-all 比对 / **双视角对照**（直连源站 IP vs 走 DNS/CDN）/ **有界下一跳追问**。
> 实测（2026-10-15 公网 34 条）：自动排除 3 条误报，与人工复核结论完全一致。

**② 人工抽查（抓真实响应，人眼判断）**：
```bash
python3 tools/verify_layer.py --findings scan_result_xxx/findings.jsonl --out verify_out --no-ai
```
或手动 curl：
```bash
curl -s -o /dev/null -w "%{http_code}\n" --max-time 5 "http://目标/druid/login.html"
curl -s --max-time 5 "http://目标/actuator/env" | head -c 300
```
> 判定：200 且内容是真实 actuator/druid 数据 → 真暴露；200 但返回的是首页/统一错误页 → **catch-all 误报**。

## 4. 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `存活 Web 服务 0` | 网络不可达 / fake-ip 代理环境 / 域名解析失败 | 按第 0 节自检连通性；换授权内网环境；查 scan.log 中"域名解析失败" |
| 命中数异常偏少 | 目标经 WAF/CDN、或应用在嵌套上下文 | 补资产入口 URL（带 /context 前缀）；确认 `--timeout` 够大 |
| 个别端点 302/401 | 登录跳转或需认证 | 属正常发现：302 到登录页=存在但需登录，按"需认证"对待 |
| druid 未报弱口令 | 非默认口令 | 仅内置默认口令表，其余不爆破；人工确认后可另行处理 |

## 5. 合规与交付

1. 每个资产文件、每次扫描的输出目录、审计日志一并留存（可作为自查证据链）；
2. `report.md` 中"严重项（默认口令可登录）"优先整改；命中端点按整改建议收敛（网关/WAF 加 URL 黑名单、Actuator 仅留 /health、Swagger 仅 dev、Druid 强口令+白名单）；
3. 处置完成后**复扫验证收敛**（对同一资产文件再跑一遍，命中应显著下降）；
4. 如发现疑似已被利用痕迹（异常登录、篡改），按组织安全事件流程上报，勿自行处置。
